# DBBETZ.COM — Conversion Plan

**Date:** 2026-08-20 | Built on `DBBETZ-CONVERSION-AUDIT.md`. Real evidence: the site's CTA system is already sound — this plan is about preserving what works and closing the one real trust gap found, not a redesign.

## Internal CTA Strategy

| Content type | Next-step CTA | Real example |
|---|---|---|
| Support/troubleshooting guide | Related guide or tool, not a hard sell | Support posts → each other (cross-linked) + `/how-to-start/` + the tax calculator |
| Tool (calculator) | Explanation/context, not an immediate registration push | `/betting-tax/`'s calculator sits inside the explainer, existing CTA banner stays at page-end only |
| Educational article | Relevant resource | `/how-to-bet/` → `/betting-tax/`; `/betting/` → `/how-to-bet/` and `/betting-tax/` |
| Onboarding guide | Direct commercial action | `/how-to-start/` → real "Jisajili"/"Anza sasa" CTAs, already appropriately placed after each real step |
| Commercial/product page | Outbound registration | `/betting/`, `/casino/`, `/bonuses/` → tracked affiliate link |

No changes recommended to this structure — real evidence (Part 12's audit) found it already matches intent correctly.

```
CONVERSION IF MEASURABLE — NOT CURRENTLY VISIBLE to DBBETZ; the partner (DBBet) holds registration/deposit conversion data, not shared with this site. Do not assume or estimate a conversion rate that isn't actually known.
```

## A/B Testing

**Not run this cycle — traffic volume doesn't justify it.** Real baseline (Part 7): 9–34 clicks per period. Any A/B test at this volume would take months to reach a meaningful sample and risks drawing a false conclusion from noise. No test defined or launched — matches this phase's own explicit instruction not to test with insufficient traffic.

## Trust Over Conversion — the standard applied this phase

Every candidate change was screened against this question: does it increase clicks at the cost of trust? The one substantial change made (the affiliate disclosure) is the opposite case — a change that reduces the risk of a perceived-deception problem even though it doesn't increase clicks and arguably could very slightly reduce naive click-through by making the commercial relationship explicit. It was implemented anyway, because trust is this phase's explicit, stated priority #1.
